# unycfd

A tiny, blazingly fast, low-memory Cloudflare Tunnel (`cloudflared`) implementation in pure Rust.

Designed as a drop-in, lightweight replacement for the official Go-based `cloudflared` binary, specifically tailored for high networking performance and minimal memory footprint (< 3 to 4 MB RSS) on edge and container nodes.

---

## Key Highlights

- **Ultra-Low Memory Footprint**: Runs at **~2.8 – 3.6 MB RSS** (compared to official `cloudflared`'s ~35 – 65 MB).
- **High-Performance QUIC Transport**: Built on `quinn` with ALPN `argotunnel`, 0-RTT/1-RTT connection setup, avoidance of TCP head-of-line blocking, and automatic HTTP/2 fallback.
- **Full Named Tunnel Support**: Directly loads Cloudflare Tunnel JSON credentials (`AccountTag`, `TunnelSecret`, `TunnelID`) as generated by Cloudflare API and `cloudflared`, or Zero Trust dashboard connector tokens (`--token`).
- **Full Ingress Routing**:
    - `unix:/path/to/socket` (Unix domain sockets, e.g. OpenResty `/run/openresty/nginx.sock`)
    - `http://127.0.0.1:PORT` (TCP HTTP services)
    - `http_status:404` / `http_status:XYZ` (native error responses)
    - Bidirectional WebSocket upgrade streaming
    - Wildcard hostname routing (`*.sub.domain.com`) and path routing
- **Systemd `Type=notify` Support**: Native integration with `$NOTIFY_SOCKET` (`READY=1`, `STATUS=...`, `STOPPING=1`), allowing systemd unit template `cloudflared@.service` to transition to active immediately after edge registration.
- **Quick Tunnel Support**: Single-flag quick tunnel generation (`unycfd --url http://localhost:8080`) for instant sharing via `trycloudflare.com`.

## Architectural Comparison & Foundation

Between the two reference implementations:

| Feature                 | `cloudflare-quick-tunnel-rs` | `libcfd`                                       | **unycfd**                              |
| :---------------------- | :--------------------------- | :--------------------------------------------- | :-------------------------------------- |
| **Named Tunnels**       | ❌ No (quick tunnel only)    | ✅ Yes (`from_credentials_file`, `from_token`) | ✅ Yes                                  |
| **Edge Protocol**       | QUIC + `capnp-rpc`           | QUIC (`quinn`/`quiche`) + HTTP/2 (`h2`)        | ✅ QUIC + HTTP/2 fallback               |
| **Cap'n Proto RPC**     | `capnp-rpc` crate            | Standalone `libcfd-rpc` crate                  | ✅ Clean `libcfd-rpc` layer             |
| **Ingress Proxying**    | In-process HTTP handler      | Abstract traits (`HttpOrigin`, `StreamOrigin`) | ✅ Unix socket + HTTP + WS + 404 router |
| **CLI & YAML Drop-in** | ❌ No                        | ❌ No (library only)                           | ✅ Drop-in CLI & YAML compatible        |
| **Systemd sd_notify**   | ❌ No                        | ❌ No                                          | ✅ Native `READY=1` & `STOPPING=1`      |
| **Memory Footprint**    | ~15–20 MB                    | ~10–15 MB (unoptimized)                        | **< 3–4 MB RSS**                        |

`libcfd` was selected as the superior protocol foundation because it cleanly handles named tunnel RPC handshakes, connection authentication secrets, remote configuration pushes, and transport negotiation.

## How unycfd Achieves < 3 MB Memory Footprint

1. **Single-Threaded Current-Thread Tokio Runtime**: Standard multi-threaded runtimes allocate worker threads and stacks (often 2–8 MB virtual memory each) plus multiple thread-local allocator caches. `unycfd` uses `tokio::runtime::Builder::new_current_thread().enable_all()`, eliminating worker thread stack overhead.
2. **Tuned QUIC Receive Windows**: `quinn` defaults to 6 MB stream windows and 30 MB connection windows. `unycfd` tunes these to 512 KB per stream and 2 MB per connection with up to 256 concurrent bidi streams, ensuring maximum throughput while capping allocation pools.
3. **Zero-Copy Streaming**: Request and response bodies are streamed chunk-by-chunk using `tokio_util::compat` and `futures_util::io::AsyncRead` rather than buffering in memory.
4. **Allocator Arena Limiting**: Sets `MALLOC_ARENA_MAX=1` on Linux to prevent glibc malloc arena fragmentation.
5. **Compiler Optimization Profile**:
    ```toml
    [profile.release]
    opt-level = "s"      # Optimize for size and instruction cache efficiency
    lto = "fat"          # Cross-crate link-time optimization
    codegen-units = 1    # Maximum dead-code elimination & inlining
    panic = "abort"      # Strip stack unwinding tables
    strip = "symbols"    # Strip debug symbols
    ```
    Yields a standalone **3.3 MB binary** with peak RSS below **3 MB**.

## Installation & Building

```bash
# Clone the repository
git clone https://github.com/unycfd/unycfd.git
cd unycfd

# Build optimized release binary
cargo build --release

# The binary will be located at:
./target/release/unycfd
```

## CLI Usage

### 1. Run with Config File

```bash
unycfd tunnel --config /etc/cloudflared/config-main.yml run
# or shorthand:
unycfd -c /etc/cloudflared/config-main.yml
```

### 2. Run with Connector Token (Zero Trust Dashboard)

```bash
unycfd tunnel run --token <TOKEN>
# or shorthand:
unycfd -t <TOKEN>
```

### 3. Quick Tunnel Mode

```bash
unycfd --url http://localhost:8080
```

## Configuration File Example (`config.yml`)

Matches the standard configuration format:

```yaml
tunnel: 4c3e387c-658b-4b2a-a9a7-96a1a1f332ab
credentials-file: /etc/cloudflared/account_1.json
edge-ip-version: "auto"
protocol: "quic"

ingress:
    # Route domain to local OpenResty / Nginx Unix Domain Socket
    - hostname: example.com
      service: unix:/run/openresty/nginx.sock
    - hostname: www.example.com
      service: unix:/run/openresty/nginx.sock

    # Route subdomains or API to local TCP port
    - hostname: "*.api.example.com"
      service: http://127.0.0.1:8080

    # Default catch-all rule
    - service: http_status:404
```
