# unycfd

A tiny, blazingly fast, low-memory Cloudflare Tunnel (`cloudflared`) implementation in pure Rust.

Designed as a drop-in, lightweight replacement for the official Go-based `cloudflared` binary, specifically tailored for high networking performance and minimal memory footprint (< 3 to 4 MB RSS) on edge and container nodes.

---

## Key Highlights

- **Ultra-Low Memory Footprint**: Runs at **~2.8 – 3.6 MB RSS** (compared to official `cloudflared`'s ~15 – 35 MB).
- **High-Performance QUIC Transport**: Built on `quinn` with ALPN `argotunnel`, 0-RTT/1-RTT connection setup, avoidance of TCP head-of-line blocking, and automatic HTTP/2 fallback.
- **Full Named Tunnel Support**: Directly loads Cloudflare Tunnel JSON credentials (`AccountTag`, `TunnelSecret`, `TunnelID`) as generated by Cloudflare API and `cloudflared`, or Zero Trust dashboard connector tokens (`--token`).
- **Full Ingress Routing**:
    - `unix:/path/to/socket` (Unix domain sockets, e.g. OpenResty `/run/openresty/nginx.sock`)
    - `http://127.0.0.1:PORT` (TCP HTTP services)
    - `http_status:404` / `http_status:XYZ` (native error responses)
    - Bidirectional WebSocket upgrade streaming
    - Wildcard hostname routing (`*.sub.domain.com`) and path routing
- **Systemd `Type=notify` Support**: Native integration with `$NOTIFY_SOCKET` (`READY=1`, `STATUS=...`, `STOPPING=1`), allowing systemd unit template `cloudflared@.service` to transition to active immediately after edge registration.
- **Quick Tunnel Support**: Single-flag quick tunnel generation (`unycfd --url http://localhost:8080`) for instant sharing via `trycloudflare.com`.

## Workspace Architecture & Protocol Internals

Cloudflare Tunnel (`argotunnel`) multiplexes **Cap'n Proto RPC** messages over QUIC streams or HTTP/2 to register tunnels with Cloudflare's edge, maintain heartbeats, and exchange proxy streams. 

To achieve maximum performance and separation of concerns, this repository is organized as a modular Cargo workspace:

```text
unycfd (Cargo Workspace)
├── crates/libcfd-rpc  ──> Standalone Cap'n Proto RPC framing with Send futures (no thread-local runtime locks)
├── crates/libcfd      ──> Embeddable Rust client library (QUIC/quinn, HTTP/2, edge registration & named tunnels)
└── crates/unycfd      ──> Production CLI daemon (tuned single-threaded runtime, ingress router, sd_notify, < 3 MB RSS)
```

- **Why a custom RPC layer? (`libcfd-rpc`)**: Cloudflare's wire protocol requires Cap'n Proto RPC over the transport stream. The generic upstream `capnp-rpc` crate produces non-`Send` futures, binding execution to thread-local contexts. `libcfd-rpc` provides the exact RPC wire framing needed for Cloudflare Edge handshakes with clean `Send` futures that integrate seamlessly into any async executor.
- **Why an embeddable library? (`libcfd`)**: If you are writing a Rust application and want to expose an internal service via Cloudflare Tunnel without deploying an external daemon binary, you can depend on `libcfd` directly.
- **Why a tuned daemon? (`unycfd`)**: Standard multi-threaded async binaries with default Quinn buffer sizes typically allocate 10–15 MB RSS. `unycfd` packages `libcfd` into a drop-in binary that drives memory down to **< 3 MB RSS** while retaining full CLI/YAML compatibility.

---

## How unycfd Achieves < 3 MB Memory Footprint

1. **Single-Threaded Current-Thread Tokio Runtime**: Standard multi-threaded runtimes allocate worker threads and stacks (often 2–8 MB virtual memory each) plus multiple thread-local allocator caches. `unycfd` uses `tokio::runtime::Builder::new_current_thread().enable_all()`, eliminating worker thread stack overhead.
2. **Tuned QUIC Receive Windows**: `quinn` defaults to 6 MB stream windows and 30 MB connection windows. `unycfd` tunes these to 512 KB per stream and 2 MB per connection with up to 256 concurrent bidi streams, ensuring maximum throughput while capping allocation pools.
3. **Zero-Copy Streaming**: Request and response bodies are streamed chunk-by-chunk using `tokio_util::compat` and `futures_util::io::AsyncRead` rather than buffering in memory.
4. **Allocator Arena Limiting**: Sets `MALLOC_ARENA_MAX=1` on Linux to prevent glibc malloc arena fragmentation.
5. **Compiler Optimization Profile**:
    ```toml
    [profile.release]
    opt-level = "s"      # Optimize for size and instruction cache efficiency
    lto = "fat"          # Cross-crate link-time optimization
    codegen-units = 1    # Maximum dead-code elimination & inlining
    panic = "abort"      # Strip stack unwinding tables
    strip = "symbols"    # Strip debug symbols
    ```
    Yields a standalone **3.3 MB binary** with peak RSS below **3 MB**.

```bash
# Clone the repository
git clone https://github.com/unycfd/unycfd.git
cd unycfd

# Build optimized release binary
cargo build --release

# The binary will be located at:
./target/release/unycfd
```

## CLI Usage

### 1. Run with Config File

```bash
unycfd tunnel --config /etc/cloudflared/config-main.yml run
# or shorthand:
unycfd -c /etc/cloudflared/config-main.yml
```

### 2. Run with Connector Token (Zero Trust Dashboard)

```bash
unycfd tunnel run --token <TOKEN>
# or shorthand:
unycfd -t <TOKEN>
```

### 3. Quick Tunnel Mode

```bash
unycfd --url http://localhost:8080
```

## Configuration File Example (`config.yml`)

Matches the standard configuration format:

```yaml
tunnel: 4c3e387c-658b-4b2a-a9a7-96a1a1f332ab
credentials-file: /etc/cloudflared/account_1.json
edge-ip-version: "auto"
protocol: "quic"

ingress:
    # Route domain to local OpenResty / Nginx Unix Domain Socket
    - hostname: example.com
      service: unix:/run/openresty/nginx.sock
    - hostname: www.example.com
      service: unix:/run/openresty/nginx.sock

    # Route subdomains or API to local TCP port
    - hostname: "*.api.example.com"
      service: http://127.0.0.1:8080

    # Default catch-all rule
    - service: http_status:404
```

## Systemd Template Service (`unycfd@.service`)

A systemd template unit is included at [`systemd/unycfd@.service`](systemd/unycfd@.service) to manage multiple concurrent tunnels cleanly (e.g. per account or per domain):

### Installation

1. Install the unit template:
   ```bash
   sudo cp systemd/unycfd@.service /etc/systemd/system/
   sudo systemctl daemon-reload
   ```

2. Place configuration files for each instance named after the account/instance:
   * Config: `/etc/cloudflared/config-<NAME>.yml` (or `/etc/unycfd/config-<NAME>.yml`)
   * Credentials: `/etc/cloudflared/<NAME>.json` (or `/etc/unycfd/<NAME>.json`)

3. Start and enable instances individually:
   ```bash
   # Starts tunnel using /etc/cloudflared/config-account1.yml
   sudo systemctl enable --now unycfd@account1

   # Starts tunnel using /etc/cloudflared/config-account2.yml
   sudo systemctl enable --now unycfd@account2
   ```

Because `unycfd` integrates with systemd's notification protocol (`Type=notify`), systemd only marks the service as `active (running)` once registration with the Cloudflare edge is fully confirmed.

## Smoke Testing Release Binaries

Quick self-contained scripts to download the latest release binary, start a local test HTTP server on `127.0.0.1:8080`, and expose it via a Quick Tunnel (`trycloudflare.com`). Once running, open a second terminal and run `curl -i https://<your-subdomain>.trycloudflare.com/`.

### Linux (POSIX `sh` / BusyBox `ash` compatible, auto-detects arch)

```sh
#!/bin/sh
set -eu

case "$(uname -m)" in
  x86_64|amd64)  ARCH="x86_64-unknown-linux-musl" ;;
  aarch64|arm64) ARCH="aarch64-unknown-linux-musl" ;;
  *) echo "Unsupported architecture: $(uname -m)" >&2; exit 1 ;;
esac

URL="https://github.com/unycfd/unycfd/releases/latest/download/unycfd-${ARCH}"
if command -v curl >/dev/null 2>&1; then
  curl -fsSL "$URL" -o unycfd
else
  wget -qO unycfd "$URL"
fi
chmod +x unycfd
./unycfd --version

mkdir -p /tmp/unycfd-test
printf 'hello from unycfd\n' > /tmp/unycfd-test/index.html
if command -v python3 >/dev/null 2>&1; then
  python3 -m http.server 8080 --directory /tmp/unycfd-test >/dev/null 2>&1 &
else
  busybox httpd -f -p 127.0.0.1:8080 -h /tmp/unycfd-test >/dev/null 2>&1 &
fi
HTTP_PID=$!
trap 'kill "$HTTP_PID" 2>/dev/null || true' EXIT INT TERM

./unycfd --url http://127.0.0.1:8080
```

### macOS (auto-detects Apple Silicon / Intel)

```sh
#!/bin/sh
set -eu

case "$(uname -m)" in
  arm64|aarch64) ARCH="aarch64-apple-darwin" ;;
  x86_64)        ARCH="x86_64-apple-darwin" ;;
  *) echo "Unsupported architecture: $(uname -m)" >&2; exit 1 ;;
esac

curl -fsSL "https://github.com/unycfd/unycfd/releases/latest/download/unycfd-${ARCH}" -o unycfd
chmod +x unycfd
xattr -d com.apple.quarantine ./unycfd 2>/dev/null || true
./unycfd --version

mkdir -p /tmp/unycfd-test
printf 'hello from unycfd\n' > /tmp/unycfd-test/index.html
python3 -m http.server 8080 --directory /tmp/unycfd-test >/dev/null 2>&1 &
HTTP_PID=$!
trap 'kill "$HTTP_PID" 2>/dev/null || true' EXIT INT TERM

./unycfd --url http://127.0.0.1:8080
```

### Windows (PowerShell, no external tools required)

```powershell
$arch = switch ($env:PROCESSOR_ARCHITECTURE) {
  "AMD64" { "x86_64-pc-windows-msvc.exe" }
  default { throw "Unsupported architecture: $env:PROCESSOR_ARCHITECTURE" }
}

curl.exe -fsSL "https://github.com/unycfd/unycfd/releases/latest/download/unycfd-$arch" -o unycfd.exe
.\unycfd.exe --version

$server = Start-Process powershell -PassThru -WindowStyle Hidden -ArgumentList @(
  '-NoProfile', '-Command',
  '$l = [System.Net.HttpListener]::new(); $l.Prefixes.Add("http://127.0.0.1:8080/"); $l.Start(); while ($l.IsListening) { $c = $l.GetContext(); $b = [Text.Encoding]::UTF8.GetBytes("hello from unycfd`n"); $c.Response.ContentLength64 = $b.Length; $c.Response.OutputStream.Write($b,0,$b.Length); $c.Response.Close() }'
)

try {
  .\unycfd.exe --url http://127.0.0.1:8080
} finally {
  Stop-Process -Id $server.Id -Force -ErrorAction SilentlyContinue
}
```
